# Лабораторная 7: объяснение для защиты

Раньше API хранил курсы в data.py, а записи студентов — в списке ENROLLMENTS.
При перезапуске изменения исчезали. Теперь источником данных служит PostgreSQL.

## Как проходит запрос

1. FastAPI получает JSON и проверяет его Pydantic-схемой из schemas.py.
2. Depends(get_db) открывает сессию SQLAlchemy для запроса.
3. Маршрут в main.py строит select, insert или update через ORM-модели.
4. SQLAlchemy отправляет SQL в PostgreSQL через драйвер psycopg.
5. При записи commit сохраняет транзакцию, а response_model превращает результат в JSON.
6. Контекстный менеджер закрывает сессию даже при ошибке.

Пример: сначала POST /students создаёт студента и возвращает его id. Затем
POST /enrollments с courseId и studentId создаёт запись на курс. Передавать имя
вместо studentId больше нельзя: запись связана с конкретной строкой students.

| Файл | Что объяснить |

| schemas.py | Отдельные классы проверяют входной JSON и описывают ответ; это не SQL-таблицы |
| main.py | HTTP-маршруты и запросы в БД |
| alembic/env.py | Берёт тот же адрес БД и metadata; import models регистрирует таблицы |
| 0001 | Создаёт исходную схему Lab 6 |
| 0002 | Добавляет обязательный level без потери существующих строк |
| seed.sql | Сбрасывает и загружает учебные данные |

## Связи и ограничения

Один курс имеет много записей, один студент тоже имеет много записей.
Enrollment связывает Course и Student двумя внешними ключами.
UNIQUE(course_id, student_id) запрещает повторную запись на тот же курс.
UNIQUE(email) запрещает повторный email. CHECK защищают положительные credits,
неотрицательные likes и длину имени. Идентификаторы студентов и записей выдаёт
GENERATED ALWAYS AS IDENTITY, время записи — серверный now().

ON DELETE CASCADE удаляет записи удалённого студента, RESTRICT запрещает удалить
курс с записями. passive_deletes=True передаёт удаление незагруженных дочерних
коллекций базе; эксперимент с удалением студента выполнен в бонусе 5 и объяснён отдельно в BONUS.md.

## Что показать преподавателю

Запустить fastapi dev main.py и открыть /docs.

1. GET /courses?level=beginner — два курса; показать isElective и camelCase.
2. GET /stats/courses — 3, 2, 1 и нули. Нули работают благодаря LEFT JOIN
   и count(Enrollment.id), а count(*) ошибочно дал бы 1 для пустого курса.
3. Создать студента, скопировать id и записать его на web-security.
4. GET /enrollments — название курса и имя студента получены двумя JOIN.
5. Повторить запись → 409; указать неизвестный курс или студента → 404.
6. Имя из одной буквы → 422 ещё до базы.
7. Поставить лайк, перезапустить сервер, снова получить курс — лайк сохранён.
8. Показать alembic current, history, heads и check, затем файл 0002.

Лайк выполняется SQL-выражением likes = likes + 1: БД последовательно обновляет
строку даже при конкурирующих запросах. Ошибки записи определяются по точным
именам ограничений; неизвестное нарушение не скрывается за случайным HTTP-ответом.

Миграция 0002: добавить nullable level → заполнить старые строки → SET NOT NULL.
Элективные курсы получают beginner, остальные intermediate. Downgrade удаляет
поле вместе со значениями. stamp только отмечает версию, upgrade меняет схему.
Autogenerate предлагает черновик, который нужно проверить вручную.

В README есть результаты всех восьми обязательных экспериментов и журнал реальных
запусков. Намеренные ошибки исправлены; в итоговой истории только 0001 и 0002.
